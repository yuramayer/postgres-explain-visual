# Теория

## Node Type

**Node Type** - тип узла плана, элемент дерева выполнения. При `Explain Analyze` Postgres строит план из последовательности узлов. Каждый узел = одна операция над данными.

План - дерево узлов, где:
- листья - это **сканы таблиц**/индексов
- середина - join'ы, сортировки, фильтры, агрегации
- корень - финальный результат: `Aggregate`, `Limit`, `Result`

### Сканы

#### Seq Scan

**Seq Sqan** - сканирование таблиц целиком, строчказ а строчкой.

Из плюсов - дешево стартуем, без накладных расходов. Эффективный при больших выборках, когда нам нужна заметная часть таблицы.

Из минусов - читаем всю таблицу, на больших объёмах тяжёлая история.

Оптимизатор выбирает его когда считает выборку большой или не видит подходящего индекса

#### Index Scan

**Index Scan** - обычный индексный скан. По b-tree или другому индексу Postgres находит строки, затем читает сами строки по TID

> раскрыть подробнее b-tree и TID и индексы в целом

Очень эффективный подход для точечных выборок. Может использовать фильтры и сортировку

#### Index Only Scan

Читает только индекс **без доступа к таблице**, если индекс покрывает запрос и видимость строки подтверждена через VM

Это одно из самых быыстрых сканирований. Но оно требует, чтобы нужные поля были в индексе

#### Bitmap Index Scan

Первая фаза bitmap-сканов: собираем bitmap нужных строк по индексу

#### Bitmap Heap Scan

Вторая фаза: кучей читаем страницы таблицы по bitmap

Такой подход эффективны при средней выборке 5-10%. Но требует расходов на две фазы и больше памяти
